# `fixtures/global-updates/` — oracle template for the `_do_global_updates` port

Small self-contained Portage root used to capture what Portage 3.0.83
does when `profiles/updates/` holds a `move` and a `slotmove`
(backlog #576, plan Tasks 5–11). The tree is a *template*: the capture
(`portuale/LLM/evidence/2026-10-25-review/t5/capture.sh`) copies it to a
scratch dir and runs Portage there, so this committed tree is always
the untouched before-state.

The updates file (`repo/profiles/updates/1Q-2026`) carries exactly two
valid directives and no malformed lines:

- `move dev-libs/oldpkg dev-libs/newpkg` — vdb `move_ent` renames
  `var/db/pkg/dev-libs/oldpkg-1.0`, the xpak binpkg is copied to the
  `newpkg` name, world and `package.use` entries are rewritten.
- `slotmove dev-libs/slotpkg 0 1` — vdb and gpkg `SLOT` become `1`.

`dev-libs/deppkg-1.0` is installed and depends on both
(`RDEPEND`/`DEPEND` on `dev-libs/oldpkg` and `dev-libs/slotpkg:0`), so
`update_ents` has something to rewrite in every vdb entry and binpkg.

## Layout

- `repo/` — repo `gutest`: 4 ebuilds, `profiles/updates/1Q-2026`,
  `metadata/md5-cache/` generated by real `egencache --update`
  (thin-manifests repo like `repo-341`, so no `Manifest` files ship).
- `root/` — the ROOT template (= `PORTAGE_CONFIGROOT` and `ROOT`):
  `etc/portage/{make.conf,make.profile/,package.use}`,
  `var/db/pkg/…` (3 vdb entries, each with the full aux key set plus
  its `.ebuild` file), `var/lib/portage/world`, `pkgdir/` with one
  xpak (`dev-libs/oldpkg-1.0.tbz2`, composed with `portage.xpak`) and
  one gpkg (`dev-libs/slotpkg-1.0.gpkg.tar`, compressed with
  `portage.gpkg`, `BINPKG_COMPRESS=zstd`), and a `Packages` index
  generated by Portage's own `populate(force_reindex=True)` with
  `TIMESTAMP` normalized to `0` (the same convention as
  `fixtures/pkgdir/Packages`).
- No `etc/portage/repos.conf` is committed on purpose: real Portage
  resolves relative `location` entries against the process CWD, not the
  config root, so the capture generates one with an absolute path at
  setup time (later Rust tests must do likewise in their temp copies).

## Use

```sh
T=$(mktemp -d /var/tmp/gu.XXXXXX)
cp -a fixtures/global-updates/root "$T/root"   # -a: Packages records
cp -a fixtures/global-updates/repo "$T/repo"   # binpkg MTIMEs; plain
mkdir -p "$T/root/etc/portage/repos.conf"      # populate() must see
printf '[gutest]\nlocation = %s\n' "$T/repo" > \ # them unchanged or it
  "$T/root/etc/portage/repos.conf/repos.conf"   # rewrites the index
```

`cp -a` matters: with default `FEATURES` (`pkgdir-index-trusted`) a
plain `populate()` re-indexes — and rewrites `Packages` — whenever a
binpkg mtime differs from the recorded `MTIME`.
