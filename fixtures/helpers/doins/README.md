# doins oracle (plan #326 S6, decisions D3/D4)

Expected values for the native port of `3rdparty/portage/bin/doins.py`,
generated by RUNNING the real ebuild-helpers/doins wrapper (which builds
the doins.py argv) with `PORTAGE_PYTHON` pointed at an argv-logging shim
that re-execs `/usr/bin/python`, so every run is real. The Rust tests in
portuale read these through its `fixtures` symlink
(`portuale/fixtures -> ../pmtest/fixtures`), so they run without a
Portage checkout. Regenerate with `fixtures/helpers/generate-doins.sh`.

## Layout

Per case (`doins/<case>/`), checked in by hand (the inputs):

- `cmd`: the helper-level argv, one line (`<helper> <args...>`, ASCII,
  space-separated), run with cwd=`<SRC>`.
- `env`: every variable the wrapper reads, `KEY=value` lines in LC_ALL=C
  sorted order; empty value means unset. Scratch paths use placeholders:
  `@ED@` (D and ED), `@T@` (T), `@DISTDIR@`
  (PORTAGE_ACTUAL_DISTDIR), `@CHECKOUT@` (the Portage checkout),
  `@PYSHIM@` (the argv-logging shim). The generator validates the key set
  and substitutes the placeholders, so the file doubles as the scrubbed
  record. The full set is: CATEGORY, D, DIROPTIONS, DOINSSTRICTOPTION,
  EAPI, EBUILD_PHASE, ED, EPREFIX, FEATURES, INSOPTIONS, INSDESTTREE,
  LANG, NOCOLOR, PATH, PF, PORTAGE_ACTUAL_DISTDIR, PORTAGE_BIN_PATH,
  PORTAGE_PYM_PATH, PORTAGE_PYTHON, PORTAGE_PYTHONPATH, PORTAGE_REPO_NAME,
  PORTAGE_XATTR_EXCLUDE, T, __E_DOCDESTTREE, __E_INSDESTTREE.
  `NOCOLOR=yes` keeps die banners free of ANSI codes (display-only);
  `LANG=C.utf8` pins the interpreter's filesystem encoding check.
- `in.manifest`: the source tree (format below).
- `ed.manifest` (optional): the pre-existing ED tree.
- `dist.manifest` (optional): the PORTAGE_ACTUAL_DISTDIR tree.
- `xattrs` (optional): `<qpath> <name> <hex-value>` lines applied to the
  materialised sources.

Per case, regenerated (the oracle):

- `args`: the exact doins.py argv after the script path, one element per
  line as raw bytes. `\` is written `\\` and a newline inside an element
  `\n` (an element never contains NUL, so no other escape is needed);
  `<SCRATCH>`/`<CHECKOUT>` stand for the stage and checkout paths and
  newins' random tmpdir suffix reads `newins.RAND`, so the file is stable
  across runs. The shim guarantees exactly one python invocation per case.
- `out.manifest`: the D3 tree dump of ED after the run (format below).
- `stderr.txt`, `rc.txt`, `stdout.txt` (only when non-empty).
- `out.root.manifest`, `stderr.root.txt`, `rc.root.txt`,
  `stdout.root.txt` (only when the root run differs; every case runs as
  the invoking user and as root, each on a fresh ED copy, via
  `sudo --preserve-env=... env -i ...` (never a `VAR=x sudo` prefix).
- `README`: what the case isolates, its regression signature, the run
  shape and provenance.

`materialise.py` builds an input tree from a manifest (used by the
generator; test harnesses can reuse it).

## Input manifest format

Pure ASCII, one entry per line, sorted by the encoded path:

```
d <mode4> <qpath>
f <mode4> <qpath> [|<qcontent>]
l ---- <qpath> -> <qtarget>
h <mode4> <qpath> => <qearlier-path>
```

`qpath` is relative to the tree root (no absolute paths, no `.`/`..`);
every byte outside `[A-Za-z0-9._/+-]` is `%XX`-escaped (uppercase hex).
`<qcontent>` is the file's bytes in the same escaping (absent means
empty). `<qtarget>` is raw readlink bytes (for `l`) or an earlier entry's
in-tree path (for `h`). `@SRC@`/`@DISTDIR@` in a link target substitute
the real source/distdir trees (bytes), so absolute-symlink fixtures stay
reproducible. Every parent must be an explicit `d` entry. All source
mtimes are pinned (MTIME in materialise.py), so `-p` cases are stable.

## out.manifest format (D3 tree dump)

One line per entry, sorted by the quoted ED-relative path:

```
f <mode4> <uid> <gid> <size> sha256:<hex> <qpath> [mtime=<ns>] [hlink=<n>] [xattr:<name>=<hex> ...]
d <mode4> <uid> <gid> - - <qpath> [xattr:<name>=<hex> ...]
l ---- <uid> <gid> - - <qpath> -> <qtarget> [xattr:<name>=<hex> ...]
```

- `mode` is 4 octal digits (`----` for symlinks); `uid`/`gid` numeric.
- `size`/`sha256` cover file contents (`-` for dirs/symlinks); dir sizes
  are filesystem-dependent and never recorded.
- `mtime` (nanoseconds) appears on regular files only, and only in the
  `insopts-preserve` case: `-p` is the sole path that stamps dest files,
  and created dirs always get fresh mtimes, so they carry none anywhere.
- `hlink` groups hardlinked files by (dev, ino) in first-path order
  (`h0`, `h1`, ...; inode numbers never appear). doins.py never preserves
  hardlinks (each copy is a fresh inode), so this column is empty in every
  current case; it exists to catch a regression that linked them.
- `xattr:` columns list `user.*` attributes only (name as-is, value hex),
  sorted by name. Other namespaces are out of scope.
- Preserved absolute symlinks may point back into the stage; those paths
  are scrubbed to `<SCRATCH>` like everywhere else (sort order uses the
  ED-relative path, so nothing is reordered).

## Cases

| case | rc (user/root) | isolates |
|---|---|---|
| files-no-r | 0 | no `-r`: files install, dirs silently skipped, symlink-to-dir still installs as a link |
| dirs-only-no-r | 1 | no `-r`, dirs only: all skipped, silent doins.py exit 1 plus the die banner |
| recursive | 0 | `-r` over the standard tree (nested dirs, empty dir, rel/abs/dir symlinks, hardlink pair, dangling link, non-UTF-8 name) |
| newins | 0 | rename via `$T` staging; args source is `$T/newins.RAND/<name>` |
| insopts-mode | 0 | `insopts -m0600`: files 0600, created parents 0755 |
| insopts-preserve | 0 | `insopts -p`: files keep source mtimes (the only mtime column) |
| diropts-mode | 0 | `diropts -m0700` with `-r`: created dirs 0700, files 0755; makedirs parents stay 0755 |
| owner-root | 1/0 | `insopts -o root -g root`: user installs-but-fails (traceback, 1000:100, copied mode), root is silent 0:0 |
| unknown-lax | 0 | unknown `-v` without strict: warn, fall back to `install(1)` (see stdout.txt) |
| unknown-strict | 1 | same with `DOINSSTRICTOPTION=1`: refuse, dest never created |
| dodoc-r | 0 | `dodoc -r`: forced `-m0644`, `--helper=dodoc`, dest `usr/share/doc/$PF/` |
| doheader | 0 | dest `/usr/include/`, `-m0644` forced even at EAPI 8, `--helper=doins` |
| doconfd | 0 | dest `/etc/conf.d/`, `-m0644` forced even at EAPI 8 |
| xattr-exclude | 0 | `FEATURES=xattr` + exclude glob: only `user.keep` copied |
| missing-source | 1 | missing source: `FileNotFoundError` traceback plus die banner |
| die-eapi8 | 1 | `--helpers_can_die` (EAPI 8): `install_dir` failure propagates |
| nodie-eapi3 | 0 | same blockage at EAPI 3: logged (`install_dir failed.`) and swallowed; legacy `INSDESTTREE`, no preserve/die flags in args |
| distdir-deref | 0 | `--distdir`: abs link inside it dereferenced, abs link outside and rel link preserved |
| eapi3-copy | 0 | EAPI 3: symlinks install as target copies (a dangling link aborts instead — probed, not pinned) |
| empty-dir-r | 0 | `-r` on an empty dir counts as success |
| phase-defaults-r | 0 | `-r` with real phase defaults (`-m0644`/`-m0755`, a distdir that exists, xattr + make.globals excludes): files 0644, dirs 0755, user.* xattrs copied |
| phase-defaults-files | 0 | same env without `-r`: top-level files install 0644, links (incl. dangling and absolute) preserved |
| phase-defaults-distfile | 0 | same env, `dodoc` on an abs symlink into the distdir: dereferenced to a 0644 file |

Extra branches beyond the brief's matrix: `dirs-only-no-r` (the silent
all-skipped exit-1 path), `distdir-deref` (the distdir readlink rule),
`eapi3-copy` (no `--preserve_symlinks`), `empty-dir-r` (empty `-r`
success). Deliberately absent: the EAPI ≤ 3 `dodoc` bash-side install
loop and EAPI ≤ 4 `doheader` refusal — neither reaches doins.py, so they
have no `args` to record; all `newX` wrappers share the pinned `newins`
shape (`cp` to `$T` + `do${helper#new}`) with bash-side dest/option
presets.

## Regenerating

```
fixtures/helpers/generate-doins.sh
```

A second run on the same host is byte-identical, including the READMEs
(their `date:` line has UTC day granularity). Scratch is a tmpfs under
`/tmp`, never `/var/tmp` (utf8only ZFS here: rejects non-UTF-8 names,
hash-order readdir, different xattr support); the generator asserts
tmpfs, probes raw-byte names and `user.*` xattrs, and records both in
every README (`staging:`, `xattr-fs: user.* xattrs work on tmpfs`).
