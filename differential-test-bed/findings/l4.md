### Minimal package choice

**`porttest/setuid`** — the smallest hermetic fixture that exercises
bytes, modes **and** owners plus a vdb entry:

- 3 real ELF binaries at modes **4711 / 2755 / 1750** and a data file at
  **0600** (the only fixture that puts setuid/setgid/sticky through the
  whole path); shared parent dirs also carry a non-root owner
  (`uid/gid 1`, `bin`) distinct from the package files' `root:root`.
- Real file bytes (sha256) that survive byte-for-byte, so a bytes diff is
  meaningful.
- A normal vdb entry (`CONTENTS` with `dir`/`obj`/`sym`, `PF`, `CATEGORY`,
  `SLOT`, `BUILD_TIME`, plus `environment.bz2`).
- No `SRC_URI`, no deps beyond glibc — real Portage builds it from source
  into a gpkg in ~10 s (verified this run: 9.5 s wall).
- It is also a **gpkg** build (`BINPKG_FORMAT=gpkg`), which is the format
  `mrg` targets (§1); the existing remote tests only ever exercise the
  committed **xpak** `.tbz2` fixtures.

It is the cell that already produced the bed's first honest candidate
diff — see "Must preserve" (4) below.

Secondary cell (see the S1 cell list): **`porttest/phases`**, because the
client-side hook stage (§6 stage 2) needs a fixture that observes phase
order in the far ROOT.

### Must preserve — real-Portage evidence

**Capture A: real Portage, one merge into a fresh container `/`.**
`porttest/setuid` was built with real Portage into a local `$PKGDIR`
(`gpkg`), then merged with:

```
emerge -k --getbinpkg --oneshot --verbose --color=n porttest/setuid
```

(`capture-real-merge.sh` mirrors `layers/l1/consume.sh` staging:
`PORTAGE_CONFIGROOT=/ ROOT=/ PORTAGE_RUNNING_ROOT=/`, porttest repo +
`repos.conf`, `FEATURES="-buildpkg -cgroup -ccache -distcc -sign xattr
filecaps"`, `umask 022`.)

Evidence: `real.merge.log`, `real.meta.tsv`, `real.portage-version.txt`,
`real.files.tsv`, `real.raw-stat.txt`, `real.vdb-fields.txt`,
`real.vdb-filelist.txt`, `real.vdb.tar`.

1. **File bytes.** 19 filesystem nodes, sha256 for every regular file.
   The three binaries are byte-identical across real merge and every mrg
   run (e.g. `pt-setuid` `49df827d…`, `pt-setgid` `fc023926…`,
   `pt-sticky` `b8711f4f…`). Real merge records them in
   `real.files.tsv`; mrg records the same hashes in
   `mrg-gpkg-ssh-root.tsv`.
2. **Modes.** Real merge: `4711`, `2755`, `1750`, `0600`, `0644`,
   `0755` (shared dirs). `real.files.tsv` / `real.raw-stat.txt`.
3. **Owners.** Real merge (container runs as root): package files
   `root:root`; shared parents `/usr`, `/usr/bin`, `/usr/lib`,
   `/usr/share` are `uid 1 / gid 1` (stage3 `bin`). `real.raw-stat.txt`.
   *Caveat for S1:* the remote client is the SSH login user who owns the
   ROOT (§1/§7) — see disagreement (6): a control pair must run both
   sides as the same user or owner rows are harness noise, not signal.
4. **vdb snapshot.** `real.vdb-fields.txt` +
   `real.vdb-filelist.txt` + `real.vdb.tar`:
   `CONTENTS` (`dir`/`obj`/`sym`, md5 + mtime), `PF=setuid-1.0`,
   `CATEGORY=porttest`, `SLOT=0`, `BUILD_TIME=1790372055`,
   `DEFINED_PHASES=install`, `EAPI=8`, plus **34** vdb files. Env file
   present is **`environment.bz2` only** (no plain `environment`).
5. **Exit code.** `real.merge.rc` = **0**; `real.merge.log` ends with
   `>>> porttest/setuid-1.0 merged.` / `>>> Completed (1 of 1)`.
   (The §6 driver's own exit contract is unchanged: 0 merged/skipped,
   1 unit-failed, 255 transport; already covered by the existing
   contract tests, not re-captured here.)

**The finding this capture exists to make** — real vs mrg remote, same
gpkg, modes only:

| path | real Portage merge | `mrg` remote merge |
|---|---|---|
| `/usr/bin/pt-setuid` | **4711** | **711** |
| `/usr/bin/pt-setgid` | **2755** | **755** |
| `/usr/bin/pt-sticky` | **1750** | **750** |
| `/usr/share/porttest/pt-0600` | 0600 | 0600 (ok) |

mrg remote **drops the setuid/setgid/sticky bits** — bytes and all plain
permission bits survive; the three special bits do not. Reproduced over
`--remote-transport=local` (`mrg-gpkg-root.tsv`, `mrg-gpkg.stdout.txt`)
and over a **live loopback sshd** (`mrg-gpkg-ssh-root.tsv`,
`mrg-gpkg-ssh.stdout.txt`, `mrg-gpkg-ssh.rc.txt`, rc 0).

Root cause, localized read-only (no fix in S0):
`gpkg-image-modes.txt` extracts the gpkg's own `image.tar.zst` **as root**
inside the test container and gets `4711/2755/1750` — the archive carries
the bits. `nonroot-tar-strip.txt` extracts the same archive as the
non-root host user: default `tar -x` yields `711/755/750`; `tar -xp`
yields `4711/2755/1750`. The §6 receive stage runs `tar -xf "$BUNDLE"`
(`rust/portuale/src/remote.rs`, `unpack_script`, no `-p`), so the
extraction strips the bits before the copy stage ever sees them. This is
a **product finding for S2, not fixed here** (constraint: no product-code
fixes in S0).

### Client/server command sequence (item 4)

Captured twice against a **live loopback sshd** (the R9 far end, set up
exactly as the `loopback_sshd` fixture) and twice with
`--remote-transport=local` (the identical generated driver, no ssh — the
transport the existing tests mostly use; said explicitly so). An `ssh`
wrapper on `PATH` logged every argv.

**Per-unit ssh sequence** (`mrg-gpkg-ssh/ssh-argv.log`, 5 calls because
`porttest/setuid` defines no hooks; `mrg-ssh/ssh-argv.log`, 7 calls for
the hook-bearing `dev-libs/binpkgrmpkg-1.0` xpak fixture):

| # | argv tail | §6 stage | emitted evidence (stdout) |
|---|---|---|---|
| 1 | `… 127.0.0.1 bash -s` | 0 preflight | `>>> Remote preflight 127.0.0.1: ok` |
| 2 | `… 127.0.0.1 bash -s` | 1 receive (mkdir) | — |
| 3 | `… 127.0.0.1 sh -c cat > '<workdir>/<pf>/bundle.tar'` | 1 receive (stream) | `>>> Remote bundle <cpv>: unpacked (<n> bytes, slot <s>, repo <r>)` |
| 4 | `… 127.0.0.1 bash -s` | 1 receive (unpack+gate) | `UNPACK=ok` (internal) |
| 5 | `… 127.0.0.1 bash -s` | 2 hooks | `PHASE_setup=0`, `PHASE_preinst=0`, `>>> Remote phases <cpv>: setup ok, preinst ok` |
| 6 | `… 127.0.0.1 bash -s` | 3 copy+vdb | `MERGE_PRERM=…`, `MERGE_COPY=ok`, `MERGE_VDB=ok`, `MERGE_REMOVE=…`, `MERGE_POSTRM=…`, `MERGE_ENVUPDATE=…`, `MERGE_LEDGER=…`, `MERGE_DONE=ok`; `>>> Remote merge <cpv>: <marker>` |
| 7 | `… 127.0.0.1 bash -s` | 2/4 postinst + report | `PHASE_postinst=0`, `>>> Remote postinst <cpv>: ok`, `STATUS=merged`, `>>> Remote merged <cpv>` |

**`>>> Remote summary:` is design-only here — not observed.** The
plan-level summary line is emitted only by `run_remote_plan`
(`rust/portuale/src/remote.rs`), the multi-entry resolve/plan path. Every
S0 capture drove `--remote-binpkg` with a single package, which
`run_remote_cli` dispatches straight to `run_remote` (the single-unit
flow), so no capture stdout contains a `Remote summary` line (grep over
the run dir is empty). S1's comparator must **not** key off a summary
line; key off the per-unit tokens actually emitted (`STATUS=`,
`MERGE_*=`, `PHASE_*=`, `>>> Remote merged <cpv>`).

The preflight argv mrg builds (`ssh_argv`, `remote.rs`) is exactly
(`mrg-ssh/ssh-argv.log` line 1, abbreviated RUN path):

```
ssh -p <port> -i <client-key> -o BatchMode=yes -o ConnectTimeout=10 \
    -o StrictHostKeyChecking=accept-new -o ControlMaster=auto \
    -o ControlPersist=60s -o ControlPath=/run/user/1000/.portuale-cp/%C \
    -o UserKnownHostsFile=<RUN>/mrg-ssh/known_hosts -l vivo 127.0.0.1 bash -s
```

Every later call reuses the same base and multiplexes over ControlMaster;
only the trailing remote command differs (`bash -s` vs `sh -c cat …`).

**What lands in the far ROOT** (`mrg-gpkg-ssh-root.tsv`): the package's
`image/` tree byte-for-byte, the vdb entry
`var/db/pkg/porttest/setuid-1.0/`, and `/var/cache/edb/counter`; no
workdir survives (removed per unit). Full-merge hook fixture over ssh
(`mrg-ssh-root.tsv`, `mrg-ssh-vdb-CONTENTS.txt`): payload file, vdb entry,
and `/var/lib/binpkgrmpkg.log` = `setup-1.0\npreinst-1.0\npostinst-1.0\n`.
Owners there are the login user (`1000:100`), modes `0644` — the client
is not root.

**Exit codes observed:** all four capture runs `rc = 0`
(`mrg-local.rc.txt`, `mrg-ssh.rc.txt`, `mrg-gpkg.rc.txt`,
`mrg-gpkg-ssh.rc.txt`).

### Disagreements between real behaviour / design and what shipped

Recorded, **not resolved and not fixed** (S0 constraint).

1. **Status channel (§6/§11 vs code).** Design: each stage emits
   `portuale-remote: <stage> <rc>` on a dedicated fd, "stderr stays the
   human log". Reality: no `portuale-remote:` token exists anywhere in
   `rust/portuale/src` (grep `portuale-remote:` → only the plan doc); the
   machine tokens (`STATUS=`, `MERGE_*=`, `PHASE_*=`, `UNPACK=`) go to
   **stdout**, interleaved with the `>>>` human lines;
   `mrg-local.stderr.txt` / `mrg-ssh.stderr.txt` are essentially empty.
   S1's comparator must key off the actual tokens, not the §6 spelling.
2. **Option surface (§10 vs `mrg.rs` OPTIONS).** `--remote-keep-workdir`
   is in the §10 table but clap rejects it ("unexpected argument");
   `--remote-jobs` is likewise absent (the table calls it a reserved
   knob). The other 18 `--remote-*` options are present. (This is why the
   run's workdir could not be retained for forensics; the mode-loss root
   cause was localized by extracting the gpkg directly instead.)
3. **Stage count (§11 "one `bash -s` per stage-group").** Reality is one
   ssh invocation per sub-step: 5 (hookless) or 7 (with hooks), per unit.
   Multiplexing keeps it one TCP/auth (§4), but "stage-group" is not
   literal.
4. **Format in tests vs target (§1).** The only shipped full-remote-merge
   tests drive `--remote-binpkg` with **xpak** `.tbz2` fixtures; §1
   declares xpak out of scope and gpkg the target. This capture proves the
   gpkg path works end to end (`mrg-gpkg*.stdout.txt`), so S1 should use
   gpkg. Recorded so the S1 runner does not inherit the tbz2 habit.
5. **Modes (product bug).** Real Portage preserves setuid/setgid/sticky;
   `mrg` remote does not (see "Must preserve" 4). §6's receive stage's
   `tar -xf` without `-p` is the localized cause.
6. **Owner semantics.** Real Portage merged as root (`root:root`, parents
   `bin:bin`); the remote client is the login user who owns ROOT
   (`1000:100`). Before S1 grades any owner row it must fix the control
   pair to a single user on both sides, else every row is an artefact.

Both are EAPI=8 `porttest` overlay fixtures with no `SRC_URI`; both built
in this run (`_l31-s0-pkgcache`). Note for S1: a second build of the same
`PV` without clearing `$PKGDIR` produced a new `BUILD_ID`/`-N` archive, so
the runner should use a fresh pkgcache per run (or `L1_REBUILD=1`) to keep
the compared binpkg pinned.

`--remote-transport=local` is useful for the S1/S2 driver tests (the
existing contract tests use it), but the remote bed's control pair must be
the **live loopback sshd** — that is the R9 far end, and the local
transport cannot catch ssh-channel/quoting/owner/user differences.

**Open for S1 (not decided here):** the R9 wording ("loopback_sshd …
plus the container ROOT play the far machine") leaves the topology
ambiguous — an sshd on the host with a host `--remote-root` (what this
capture did, where the client is `uid 1000`), versus an sshd *inside* the
differential-test-bed container with the container ROOT as `--remote-root`
(where the client could be root, matching Capture A's owner rows). The
control pair's owner/mode expectations depend on that choice; page S1's
author to settle it before writing the comparator.
