## R2 ruling (controller, 2026-09-25)

**Lifecycle diffs first, fault injection second, stop between them** (the

## S1 / S2 split — resolution of the shape conflict

The batch plan (`docs/batch-2026-09-25.md` §4) says S1 is "the first four
(no fault injection)" and S2 is "disk-full / corrupt / 500"; the five-group
list in the brief is `-C`/`--depclean`, soname→preserved-libs,
`CONFIG_PROTECT`, `--resume`-after-kill, faults. Those do not line up:
group 4 (`--resume`-after-**SIGKILL**) *is* fault injection, so the plan's
parenthetical "(no fault injection)" is inaccurate.

**Resolution (recorded; matches the plan's own step numbering "first
four"):**

| Half | Cells | Groups |
|---|---|---|
| **S1 — life-cycle** (groups 1–4) | C1 `-C`/`--depclean` diffs · C2 soname bump → preserved-libs · C3 `CONFIG_PROTECT` · C4 `--resume` after SIGKILL | g1–g4 |
| **S2 — fault injection** (group 5) | F1 disk-full (ENOSPC) · F2 corrupt archive · F3 binhost HTTP 500 | g5a/g5a2, g5b, g5c |

This makes S1 "the life-cycle behaviours" (including the kill/resume state
machine) and S2 "the three fault cells", which is what "Stop and confirm
R2 before S2" and "S2: fault half. Disk-full / corrupt / 500 cells."
require. The `--resume` cell stays in S1 because it exercises the merge
state machine (mtimedb/resume/VDB), not an external fault; the two real
faults it shares a mechanism with (disk-full, corrupt) remain in S2.

4. `emerge -p @preserved-rebuild --color=n` (rc 0)
5. `emerge @preserved-rebuild --color=n` (rc 0)

**Expected output shape.**

- upgrade leaves the old files and prints the preserved-libs banner
  (`g2/upgrade.log`):

  ```
  >>> Installing (1 of 1) l32/sonamelib-2.0::l32
  >>> needed    sym /usr/lib64/libl32soname.so.1
  ```

**Preserved-libs registry** (`/var/lib/portage/preserved_libs_registry`):

- before and after rebuild: empty (`{}`; after-rebuild file has no trailing

  ```json
  			"/usr/lib64/libl32soname.so.1.0.0",
  			"/usr/lib64/libl32soname.so.1"
  		]
  	]
  }
  ```

  Comparator keys: the `cp:slot` key `l32/sonamelib:0`; the owner cpv
  `l32/sonamelib-2.0`; the path list order (`.1.0.0` then `.1`). The middle

- `sonamelib-2.0/CONTENTS` (`vdb-after-upgrade.detail.txt`) **lists the

  `sym /usr/lib64/libl32soname.so.1 -> libl32soname.so.1.0.0` and

  **No `preserved` file** is stored in the vdb (the detail section

- vdb dirs after upgrade and after rebuild: `sonamelib-2.0`,

- `sonameuser` `DT_NEEDED` before = `libl32soname.so.1`; after the bump it

## Group 4 — `--resume` after SIGKILL  (S1 cell C4)

**Fixture packages.** `l32/slow-a`, `l32/slow-b`, `l32/slow-c` — identical
except name; each `src_compile` sleeps 6s so a kill can land deterministically
between packages.

**Commands** (`logs/g4/`):

1. `setsid emerge --oneshot --usepkg=n --color=n l32/slow-a l32/slow-b
   l32/slow-c &` → SIGKILL the process group once
   `Installing (1 of 3)` is seen (`kill -9 -$SPID`), then
   `pkill -9 -f '/var/tmp/portage/l32/slow'`.
2. `emerge --resume --pretend --color=n` (rc 0)
3. `emerge --resume --color=n` (rc 0)

**Expected output shape.**

- after the kill, `/var/db/pkg/l32` contains exactly one entry:
  **`-MERGING-slow-a-1.0`** (the half-installed marker directory) and no
  `slow-a-1.0`; `ps` shows no `emerge`/`slow` processes. This
  `-MERGING-` prefix is the primary "killed mid-merge" invariant.
- `/var/tmp/portage/l32/slow-a-1.0/` workdir survives, with
  `.slow-a-1.0.portage_lockfile` at the parent.
- `mtimedb` after kill has a `resume` key with the **reverse-ordered
  favorites** and the full merge list
  (`mtimedb-resume-key.txt`):

  ```json
  {
    "binpkgs": [],
    "favorites": ["l32/slow-c", "l32/slow-b", "l32/slow-a"],
    "mergelist": [
      ["ebuild", "/", "l32/slow-a-1.0", "merge"],
      ["ebuild", "/", "l32/slow-b-1.0", "merge"],
      ["ebuild", "/", "l32/slow-c-1.0", "merge"]
    ],
    "myopts": {
      "--color": "n", "--oneshot": true,
      "--regex-search-auto": "y", "--usepkg": false
    }
  }
  ```

  The enclosing mtimedb also carries `info`, `ldpath`, `updates`,
  `starttime`, `version` (`"3.0.82.2"`); `mtimedb-after-kill.txt` is the
  full document.
- `--resume --pretend` (rc 0) re-lists all three as new installs:
  header `These are the packages that would be merged, in order:`,
  dependency-resolution line, `[ebuild  N     ] l32/slow-a-1.0`
  (and `-b`, `-c`).
- `--resume` actual (rc 0) begins
  `*** Resuming merge...` and then re-runs the works from scratch
  (`>>> Emerging (1 of 3) l32/slow-a-1.0::l32` … `>>> Completed (3 of 3)`).
  Because the kill happened during `Installing` (1 of 3), **all three**
  packages are re-merged; nothing is skipped. No package from the killed
  run is reused.
- after a **successful** resume the `resume` key is gone from
  `mtimedb-after-resume` (the file has no `resume` field). Key consumed.

**Exit codes.** `resume-pretend.rc` = `rc=0`,
`resume-actual.rc` = `rc=0`; `kill.txt` records
`killed pid=2291 after 'Installing (1 of 3)' observed`.

**VDB / ROOT deltas.** `vdb-after-kill.list` =
`-MERGING-slow-a-1.0`; `vdb-after-resume.list` =
`slow-a-1.0`, `slow-b-1.0`, `slow-c-1.0`; vdb snapshot
`vdb-after-resume/` holds all three. `/var/cache/edb/mtimedb` loses the
`resume` key on completion.

**Evidence pointers.** `g4/merge.log`, `kill.txt`, `ps-after-kill.txt`,
`portage-tmp-after-kill.txt`, `vdb-after-kill.list`,
`mtimedb-after-kill.txt`, `mtimedb-resume-key.txt`,
`resume-pretend.log`, `resume-actual.log`, `vdb-after-resume.list`,
`mtimedb-after-resume`, `*.rc`, `vdb-after-resume/`.

**Minimal fixtures.** `slow-a`, `slow-b`, `slow-c`; each compile sleeps
long enough to observe the phase boundary.

## Group 5 — fault injection  (S2 cells F1/F2/F3)

### 5a. disk-full / ENOSPC  (S2 cell F1)

Two runs into one `logs/g5-diskfull/` dir; the second overwrote the first's
`tmpfs-before.txt`. Both used a **small dedicated tmpfs mounted at
`/var/tmp/portage`** — never `/home`.

**F1a — 8 MiB tmpfs.** `emerge -q --oneshot --usepkg=n --color=n
l32/bigpkg`, fixture `l32/bigpkg` writes a 64 MiB
`/usr/share/l32/big/blob` in `src_install`.

- `merge.rc` = `rc=143` (SIGTERM, not a clean `1`).
- `merge.log`: reaches `>>> Emerging (1 of 1) l32/bigpkg-1.0::l32`, then
  Portage's own logger aborts:

  ```
  [ERROR] Exception in callback PipeLogger._io_loop_done()
  ...
    File ".../portage/util/_async/PipeLogger.py", line 157, in _io_loop
      log_file.flush()
  OSError: [Errno 28] No space left on device
  ```

- `state-after.txt`: tmpfs `8.0M … 100%`; **no `/var/db/pkg/l32/`**, no
  `-MERGING-*`, no `/usr/share/l32/big/`, no `CONTENTS`.
- `vdb-after.list` empty; `mtimedb-resume-key.txt` has `resume` for
  `l32/bigpkg` (`myopts` includes `--quiet: true`);
  `emerge --resume --pretend` rc 0 prints `[ebuild  N    ] l32/bigpkg-1.0`
  (no "These are the packages…" header because the resume was `--quiet`).

**F1b — 16 MiB tmpfs + 10 MiB ballast (deterministic install-phase ENOSPC).**
`emerge --oneshot --usepkg=n --color=n l32/bigpkg`.

- `tmpfs-before.txt`: `16M` free; `tmpfs-ballast.txt`:
  `16M 10M 6.0M 63%`.
- `merge2.rc` = `rc=143`; `merge2.log` shows the deterministic failure:

## Real-vs-design disagreements / capture limitations

1. **S1/S2 split conflict** — resolved above (S1 = groups 1–4, S2 =
   group 5). The plan's parenthetical "(no fault injection)" does not match
   the five-group list, because group 4 is itself a SIGKILL fault.
2. **No product code, but two Portage 3.0.82.2 behaviours matter to the
   design:**
   - the vdb holds **no `_cfg`/`_cfgpro` marker** and **no `preserved`
     file**; the only artifacts are the on-disk `._cfg0000_*` /
     `/var/lib/portage/preserved_libs_registry`. Any portuale design that
     expects a vdb marker is a real-vs-design disagreement.
   - `--resume` re-merges **from the start of the merge list** and consumes
     the `resume` key only on success; it does not skip the interrupted
     package. Portuale must match the mtimedb `favorites` (reversed) /
     `mergelist` shape and the `*** Resuming merge...` prefix.
3. **F2 corrupt cell is not clean** — the test root already had
   `faultpkg-1.0`, so "no partial vdb entry" is unproven; only the digest
   failure shape and rc `1` are trustworthy. Re-capture on a clean root.
4. **F3b fallback is not clean** — source fallback was selected but the run
   died with `OSError: [Errno 28]` and rc `143`; re-capture on a root with
   free space before using it as an S2 oracle. F3a (fail, rc 1) is clean.
5. **disk-full rc is 143, not 1** (both F1a and F1b). The ENOSPC appears
   first as a Portage-internal `PipeLogger` flush crash on Python 3.14. The
   S2 comparator should key on the message shape
   (`OSError: [Errno 28] No space left on device`, `dd: error writing
   ... No space left on device`, `ERROR: … failed (install phase)`) and on
   the VDB/workdir delta, not on exit code alone.
6. **Pretend-vs-actual shape gap:** `-p -C` omits the
   `Waiting 5 seconds`/`Unmerging in: 5 4 3 2 1`/`Unmerging (1 of 1)` block
   that the actual `-C` prints; `--depclean` actual replaces
   `Number to remove` with `Number removed`. A comparator must key on the
   right set per invocation.
7. **Pre-flight profile missing:** `df -h /home`, `df -i /tmp`, and
   `nice -n 19` are required by the brief but are not present in the run
   dir. S1/S2 must record them per cell (and keep the disk-full cell on a
   dedicated tmpfs, as here).
8. **The `--depclean` actual can be safety-blocked** — the capture only ran
   it because `depclean-pretend-after.outside-count` was `0`. The bed must
   reproduce that guard: never let `--depclean` target non-fixture
   packages.
9. **Soname registry middle field (`464`)** is opaque Portage state; the
   comparator should key on `cp:slot`, owner cpv, and the path list, and
   ignore that integer.
